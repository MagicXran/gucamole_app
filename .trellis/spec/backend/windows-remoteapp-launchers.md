# Windows RemoteApp Launcher Contract

## Scenario: Controlled application launcher published as an RDS RemoteApp

### 1. Scope / Trigger

- Trigger: a Windows application ignores `remote-app-dir`, remembers an unsafe local path, or needs a fixed session-local entry for `\\tsclient\用户空间`.
- Current implementation: app6 publishes `||portal-freecad`, which points to the native `PortalFreeCADLauncher.exe`.
- This contract does not replace RDPDR, `/drive/portal_u{user_id}`, Windows SID/ACL isolation, or the original application alias.

### 2. Signatures

```powershell
powershell -File scripts\windows\install-portal-freecad-launcher.ps1 -PlanOnly
powershell -File scripts\windows\install-portal-freecad-launcher.ps1
powershell -File scripts\windows\install-portal-freecad-launcher.ps1 -Remove
```

```text
RemoteApp alias: portal-freecad
Launcher path: C:\ProgramData\NercarPortal\PortalFreeCADLauncher.exe
Target UNC: \\tsclient\用户空间
Session drive: U:
Portal app value: remote_app=||portal-freecad
```

### 3. Contracts

- The launcher accepts no command-line arguments.
- Wait for the fixed UNC with condition polling; do not use a blind startup delay.
- If `U:` is unmapped, map it to the fixed UNC. If it already maps to the same UNC, reuse it. If it maps elsewhere, stop without disconnecting it.
- Set both `FileOpenSavePath=U:/` and `BaseApp/Preferences/Dialog/DontUseNativeDialog=true` before starting FreeCAD. The Qt file dialog must keep `U:` in its explicit sidebar and must not enumerate the raw Windows RDPDR namespace entry.
- Start the GUI with `U:\` as its working directory.
- Remove only a drive mapping created by the current launcher process.
- Keep `drive-path=/drive/portal_u{user_id}` generated by the Portal connection builder. The friendly `U:` label is not an authorization boundary.
- The installer must validate the complete alias state: `Name`, `Path`, `VPath`, `RequiredCommandLine`, `CommandLineSetting`, `IconPath`, `IconIndex`, and `ShowInTSWA`.
- The manifest must record both deployed source SHA-256 and EXE SHA-256. Compile a temporary EXE with explicit UTF-8 source decoding before modifying deployed source, EXE, or registry state.
- Back up source, EXE, manifest, legacy launcher, and alias before replacement. If any later file, registry, or manifest step fails, restore the backed-up state before returning an error.

### 4. Validation & Error Matrix

| Condition | Required behavior |
|---|---|
| Target UNC does not appear before timeout | Launcher exits non-zero and logs `target_unavailable` |
| `U:` maps to another target | Launcher exits non-zero; existing mapping is preserved |
| FreeCAD or FreeCADCmd is missing | Launcher exits non-zero before starting the GUI |
| FreeCAD preference file starts without `DontUseNativeDialog` | Launcher writes the preference before the GUI starts; the real open/save dialog is Qt-based and omits the raw RDPDR item |
| Any external argument is supplied | Launcher exits with rejected-argument status |
| Alias exists but any managed property differs | Installer refuses overwrite/remove as an unknown alias |
| Source matches but EXE/manifest hash does not | Installer treats deployment as changed and rebuilds |
| Compile fails | Installer changes no deployed source, EXE, or registry state |
| File/registry/manifest replacement fails after backup | Installer restores the previous files and alias, then exits non-zero |
| Remove sees incomplete or modified artifacts | Installer refuses before deleting the alias |

### 5. Good / Base / Bad Cases

- Good: `U:` is free, the UNC appears, source/EXE/manifest agree, and FreeCAD's Qt dialog opens and saves under the current user's `/drive/portal_u{id}` without showing the raw RDPDR item.
- Base: `U:` already points to the same UNC; the launcher reuses it and does not remove it on exit.
- Bad: only the new source was copied while the old EXE remained. The next install must rebuild; it must not report `changed=false`.
- Bad: an alias has the expected Path but a different VPath or IconPath. Treat it as unknown, not managed.

### 6. Tests Required

- Compile the C# source with the Windows .NET Framework compiler.
- Parse the installer with Windows PowerShell 5.1.
- Assert fixed UNC, drive, executable paths, argument rejection, conditional wait, mapping ownership, `FileOpenSavePath`, and `DontUseNativeDialog` updates.
- Assert PlanOnly JSON, complete alias property checks, source/EXE manifest hashes, compile-before-copy order, and remove-before-delete integrity checks.
- Assert Portal connection output preserves `remote-app=||portal-freecad`, empty external arguments, and `/drive/portal_u{user_id}`.
- Run a real browser RemoteApp check for the Qt open/save dialog, absence of the raw RDPDR item, default `U:\` path, actual file persistence, cleanup, and a second Portal user's distinct directory.

### 7. Wrong vs Correct

#### Wrong

```text
Copy new source -> compile/replace EXE -> compare only source hash later
```

This can leave new source with an old EXE and falsely report an unchanged deployment.

#### Correct

```text
Compile temporary EXE -> back up existing state -> replace source and EXE -> publish exact alias -> write source and EXE hashes to manifest
```

Every later install validates source, EXE, manifest, and the complete alias before returning `changed=false`.
